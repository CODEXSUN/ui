# Comments Thread

Public import: `@workspace/ui/blocks/comments-thread` (also exported from the package root).

CommentsThread owns reusable presentation and interaction only. Hosts supply ThreadComment rows with string author labels, plain text, ISO timestamps, revision and canEdit/canDelete hints. Optional create/edit/delete callbacks control persistence; absent callbacks hide actions. No Comments add-on, app API, identity model or database dependency enters shared UI.

Supply canCreate, loading/loadingMore, error, unavailable, hasMore, onRefresh/onLoadMore and domain validateText as needed. Use safe user-facing error/actionError values. Set blocked after uncertain mutation outcomes; clear it only after deliberate reconciliation. Callbacks reject on failure and resolve only after confirmed success. The thread catches raw callback errors and displays fixed feedback; draft text remains until success or explicit cancellation. The edit callback receives a copied item snapshot/revision from when editing opened; current edit capability is rechecked before submission. Delete confirmation similarly keeps the revision displayed when it opened. Invalid dates display Date unavailable. Shared UI does not silently update a dirty draft to a new revision after props refresh.

Deletion requires shared confirmation. Status/error roles, named controls, linked field labels, invalid state, Escape-to-cancel editing and explicit Clear draft support keyboard users. Cancel/clear/refresh reset validation state; validator exceptions become fixed safe feedback. Rendering uses escaped text and shared semantic styles; themes and provider remain host-owned. Preserve no-store/authorization at the product boundary; hidden/disabled controls are not security enforcement. On tenant/actor/session/target/client identity change, the host must remount its panel with a new React key or pass a changed non-secret resourceKey to the shared block. This clears private drafts/action state; the host must separately clear rows and abort/invalidate stale reads. UI ignores mutation completions after unmount, without pretending an issued mutation was rolled back. The Comments add-on's browser panel implements this boundary.

The workspace has a pending UIUX usage/state preview under Blocks → Shared Blocks → Comments Thread; it is not part of the currently approved UIUX0.1.11 deployment. This release verifies11 shared DOM tests,7 consuming Comments browser tests, strict packed public imports and actual360/768/1440/1920/2560 light/dark widths. Hosts import @workspace/ui/styles.css once and provide the shared DesignSystemProvider. No provider, auth, data or backend is embedded by this block. These checks do not certify comprehensive assistive-technology support. See supervisor-audit-20261119-comments.md for exact evidence and dependency handoff.
